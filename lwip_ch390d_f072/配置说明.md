# STM32F072VBT6 内部时钟版 CubeMX 配置说明

日期：2026-11-04。

本目录的 `lwip_ch390d.ioc` 对应 `docs/网口控制器2-V1.0.pdf`，用于在独立目录生成 STM32F072 新工程。旧工程 `lwip_ch390d/lwip_ch390d.ioc` 和旧版源码不作替换。

本目录已在 CubeMX 生成工程上加入第一阶段移植代码，详见第 12 节：CH390、lwIP、TCP/UDP、Flash 参数存储和 USB CDC 配置收发已接入。两个旧 IO 控制函数保持逐字节原样复制，通道映射暂不适配新板。

## 1. 配置概要

| 项目 | 本版配置 |
| --- | --- |
| MCU | STM32F072VBT6，LQFP100，Cortex-M0，128 KB Flash、16 KB SRAM |
| CPU 时钟 | HSI 8 MHz → PREDIV /2 → PLL ×12 = 48 MHz；/2 必须显式配置 |
| AHB / APB / SPI2 外设时钟 | 48 MHz，分频均为 1 |
| USB 时钟 | 内部 HSI48 48 MHz，CRS 使用 USB SOF 自动校准 |
| 外部 HSE / LSE | 均不启用；PF0、PF1、PC14、PC15 用作 GPIO |
| RTC | 内部 LSI，标称 40 kHz；保留旧项目日历功能 |
| SPI | SPI2，主机、双线全双工、8 bit、MSB first、Mode 3、软件 NSS |
| SPI SCK | 48 MHz / 4 = 12 MHz；初次调试可改 /8 得到 6 MHz |
| CH390 INT | PD8 输入、下拉，按旧项目的高有效方式在主循环轮询 |
| 输出 | 78 路，推挽、无上下拉、低速、初始低电平 |
| USB | 原生 USB FS Device，CDC 虚拟串口；收发缓冲各 128 B |
| 调试 | SWD：PA13、PA14；JP1 保留 NRST |
| 系统时基 | SysTick，1 ms；裸机，不启用 RTOS |
| 代码生成 | HAL，分外设生成 `.c/.h`，MDK-ARM V5 |
| C 库 Heap / Stack | 0x200 / 0x800，即 512 B / 2048 B |
| STM32Cube 固件包 | STM32Cube FW_F0 V1.11.5 |

文件版本字段使用本机 CubeMX 6.18.1 / DB.6.0.181。使用较旧 CubeMX 时，建议升级到相同或更新的正式版本，再进行打开和保存；不能保证较旧版本直接识别较新的数据库版本。

配置中 `RCC.HSE_VALUE=8000000` 仅是 CubeMX 的外部时钟标称字段，不代表启用了 HSE。判断是否使用外部晶体，应检查 PF0/PF1 的 GPIO 配置和生成的 `RCC_OscInitStruct`。

选用 HSI+PLL 作为系统时钟、HSI48 单独供 USB，是为了让 CPU、SPI 和以太网运行不依赖 USB SOF。未插 USB、USB 挂起或断开时，系统时钟继续运行；USB 精度由有 SOF 时的 CRS 校准保证。内部 RC 仍存在温漂，不能当作精密计时基准。

### 1.1 时钟和 SPI2 修正记录

首次交付误把 F072 的 HSI 路径当作固定先除以 2，而文件中却配置了 `RCC.PLLDivider=RCC_PREDIV_DIV1`。用户提供的 CubeMX 截图确认实际结果是 **8 MHz /1 ×12 = 96 MHz**，超过 CPU、AHB 和 APB 的 48 MHz 上限。

F072 属于 DIE448，其 CubeMX 时钟路径是 `HSI → PLL Source Mux → PREDIV → PLL`。本次已将实际生效的配置改为：

```ini
RCC.PLLSourceVirtual=RCC_PLLSOURCE_HSI
RCC.PLLDivider=RCC_PREDIV_DIV2
RCC.PLLMUL=RCC_PLL_MUL12
RCC.VCOOutput2Freq_Value=4000000
RCC.SYSCLKSource=RCC_SYSCLKSOURCE_PLLCLK
SPI2.BaudRatePrescaler=SPI_BAUDRATEPRESCALER_4
```

SPI2 的报错不是 PB13/PB14/PB15 引脚或 Mode 3 错误：原错误 PCLK1=96 MHz，/4 得到 24 Mbit/s，超过 F072 SPI 的 18 Mbit/s 上限，因而 SPI2 参数页也出现红色错误。修正 PREDIV 后，PCLK1=48 MHz、SPI2=12 Mbit/s，保留 /4 即可。不要改用 /2，否则 48 MHz /2 仍会得到超限的 24 Mbit/s。

`.ioc` 中的 `SYSCLKFreq_VALUE`、`PLLCLKFreq_Value` 和 `SPI2.CalculateBaudRate` 是计算结果字段；把这些字段手写成 48 MHz / 12 Mbit/s 并不能覆盖错误的分频和倍频选择。必须核对实际生效的 PREDIV、PLLMUL、AHB/APB 分频和 SPI 分频。

## 2. 新旧工程差异

| 功能 | 旧工程实际配置 | 新版配置 |
| --- | --- | --- |
| MCU / 内核 | STM32G070RBT6 / Cortex-M0+ | STM32F072VBT6 / Cortex-M0 |
| 系统时钟 | HSE 8 MHz，PLL 输出 64 MHz | HSI 8 MHz，PLL 输出 48 MHz |
| CH390 SCK | PA1 / SPI1 | PB13 / SPI2 |
| CH390 MOSI / SDI | PA2 / SPI1 | PB15 / SPI2 |
| CH390 MISO / SDO | PA6 / SPI1 | PB14 / SPI2 |
| CH390 SCS | PA4 | PB12，初始高电平 |
| CH390 INT | PA0 | PD8 |
| 配置通讯 | USART1：PB6 TX、PB7 RX，经 USB 转串口 | PA11/PA12 原生 USB CDC |
| PB6 / PB7 | USART1 | GPIO 输出 |
| PF0 / PF1 | HSE 晶体引脚 | GPIO 输出 |
| SRAM | 旧构建使用 28,880 B | 芯片总共只有 16,384 B，必须缩减 |

旧 `.ioc` 同时启用了 PA0 EXTI 和主循环 INT 电平轮询，但网络处理实际在主循环中进行。本版直接使用 GPIO 输入轮询，不启用 EXTI4_15，避免误将包含延时和 SPI 访问的 `ch390_int_handler()` 放入中断处理函数。

## 3. CH390 接口与驱动修改

| MCU 引脚 | LQFP100 管脚号 | 网络 / 功能 | 初始或工作状态 |
| --- | --- | --- | --- |
| PB12 | 51 | SCS / CH390_CS | 推挽输出，初始高，低有效片选 |
| PB13 | 52 | SCK | SPI2_SCK，AF0，CPOL=1 |
| PB14 | 53 | SDO | SPI2_MISO，AF0 |
| PB15 | 54 | SDI | SPI2_MOSI，AF0，CPHA=1 |
| PD8 | 55 | INT / CH390_INT | 输入，下拉，高有效轮询 |

`CH390_Interface.c` 至少需要以下迁移，不能只替换 `.ioc`：

```c
#include "stm32f0xx_hal.h"
#include "spi.h"

extern SPI_HandleTypeDef hspi2;

#define ch390_cs(value) \
    HAL_GPIO_WritePin(CH390_CS_GPIO_Port, CH390_CS_Pin, (GPIO_PinState)(value))

uint16_t ch390_get_int_pin(void)
{
    return HAL_GPIO_ReadPin(CH390_INT_GPIO_Port, CH390_INT_Pin) == GPIO_PIN_SET;
}

/* 原来的 HAL_SPI_TransmitReceive(&hspi1, ...) 改为 &hspi2。 */
```

在 CH390 初始化完成、开始轮询前，显式统一 INT 输出类型和极性：

```c
ch390_default_config();
ch390_int_pin_config(INCR_TYPE_PP, INCR_POL_H);
```

旧 `ethernetif.c` 的 `low_level_init()` 已调用 `ch390_default_config()`，应在该调用后配置 INT，避免重复初始化整个网卡。若以后改用低有效开漏 INT，必须同时改为上拉输入，并反转 `ch390_get_int_pin()` 的判断。

SPI 保持旧工程的 Mode 3，不直接改成其他 SPI 模式。PB12 是普通 GPIO 片选，不是 SPI2 硬件 NSS；NSS pulse 关闭。

新版 CH390 的 RSTB 未接 MCU，不能在代码里虚构复位控制引脚。沿用驱动的软件复位方案，并在实际板上验证冷启动、热复位和仅复位 MCU 的恢复行为。

## 4. 78 路输出与接口映射

下表按照连接器物理引脚排列。所有 H1～H13 的 pin 1 为 12 V、pin 2 为 GND；pin 3～8 为经 TXS0108E 转换后的逻辑信号，**不是 12 V 输出**。

| 接口 | pin 3 | pin 4 | pin 5 | pin 6 | pin 7 | pin 8 |
| --- | --- | --- | --- | --- | --- | --- |
| H1 | PA10 | PA9 | PA8 | PC9 | PC8 | PC7 |
| H2 | PC6 | PD15 | PD14 | PD13 | PD12 | PD11 |
| H3 | PD10 | PD9 | PB11 | PB10 | PE15 | PE14 |
| H4 | PE13 | PE12 | PE11 | PE10 | PE9 | PE8 |
| H5 | PE7 | PB2 | PB1 | PB0 | PC5 | PC4 |
| H6 | PA7 | PA6 | PA5 | PA4 | PA3 | PA2 |
| H7 | PA1 | PA0 | **PF3** | PF2 | PC3 | PC2 |
| H8 | PC1 | PC0 | PF1 | PF0 | PF10 | PF9 |
| H9 | PC15 | PC14 | PC13 | PE6 | PE5 | PE4 |
| H10 | PE3 | PE2 | PE1 | PE0 | PB9 | PB8 |
| H11 | PB7 | PB6 | PB5 | PB4 | PB3 | PD7 |
| H12 | PD6 | PD5 | PD4 | PD3 | PD2 | PD1 |
| H13 | PD0 | PC12 | PC11 | PC10 | PA15 | PF6 |

GPIO 标签按真实芯片引脚命名，例如 `OUT_PA00`、`OUT_PF03`。每个输出有对应的 `OUT_xx_Pin` 与 `OUT_xx_GPIO_Port` 宏，应用层应使用这些宏或独立的输出映射表。

原理图 U2 pin 22 是 PF3，但其网络写成 PF04，经过 U8 到 H7 pin 5 的网络又写为 OPF04。本 `.ioc` 使用实际存在的 PF3；不能配置不存在的 PF4 来匹配错误名称。原理图另有 OPDB10/OPDB11 命名，实际对应 PB10/PB11，本配置同样按真实 GPIO 命名。

78 路输出 + 5 路 CH390 + 2 路 USB + 2 路 SWD = 87 路 GPIO，已用满该封装全部 87 路 I/O。BOOT0 是独立启动输入，不在输出集合中。需要增加硬件 UART 或外部晶体时，必须重新分配现有引脚。

输出统一设置为低速、初始低，是用于静态控制的初始配置；GPIO speed 是驱动转换速率设置，不是业务翻转频率。PC13/PC14/PC15 还须遵守芯片的 2 MHz、30 pF 和禁止作电流源等限制。TXS0108E 也不能当作功率驱动器。

TXS0108E 的 OE 在现有电路中固定接 3.3 V，MCU 复位期间输出没有软件可控的统一关断机制。因此“初始低”仅保证 `MX_GPIO_Init()` 执行后的 MCU 状态，不保证上电到初始化前连接器始终为低。如果外部负载不允许上电脉冲，需要硬件 OE 或负载使能控制。

旧 40 路控制协议的通道号不能直接当作新接口 pin 顺序。应先保留旧通道号对应的真实 GPIO，再明确规定新增通道编号；不要静默改变原有 TCP 命令含义。

## 5. 原生 USB CDC 与电阻装配

默认按原理图标注装配：

| 元件 | 默认状态 | 作用 |
| --- | --- | --- |
| R4 / R5 | 0 Ω | PA12→D+、PA11→D- |
| R9 / R12 | 0 Ω | PA10、PA9 分别送出到输出转换电路 |
| R3 / R7 | NC | 不把 PA12/PA11 接到输出转换电路 |
| R8 / R11 | NC | 不把 PA10/PA9 接到 USB 转串口芯片 |
| U14 / X2 及其配套 NC 元件 | 不装 | 本版不使用独立 USB 转串口 |

USB 使用 PA11=DM、PA12=DP；PA9/PA10 继续作为输出。不要同时装 R3+R9 或 R7+R12，否则会把两个 MCU 引脚接到同一个输出网络。若启用 U14 或更换装配选项，必须同步重新配置 `.ioc`。

CubeMX 中 USB_DEVICE 选择 CDC，生成 `usb_device.c`、`usbd_cdc_if.c` 和 USB IRQ；CDC RX/TX 用户缓冲各为 128 B。禁止沿用某些示例中数 KB 的大缓冲默认值。

USB CDC 不是 UART 硬件。旧项目直接访问 `USART1->ISR/TDR` 的 `fputc()`、`HAL_UART_Receive_IT()` 和 UART 环形缓冲必须改造。建议在 `CDC_Receive_FS()` 中仅复制数据、立即重新挂接接收，在主循环解析原来的配置协议；正确处理分包和粘包，不能假定一次 USB 回调恰好是一帧。

`CDC_Transmit_FS()` 返回 `USBD_BUSY` 时应排队或稍后重试，发送完成前不能改写发送缓冲。未连接 USB 主机时不要阻塞网络初始化或无限等待 USB 枚举；CDC 标称波特率也不会改变 USB 总线时钟。

CRS 使用内部 USB SOF 路径，不占 PF0，不需要打开 USB 的 SOF CPU 中断。生成后应确认：

```c
__HAL_RCC_CRS_CLK_ENABLE();
/* Prescaler=DIV1, Source=USB, Polarity=RISING,
   ReloadValue=47999, ErrorLimitValue=34, HSI48CalibrationValue=32 */
HAL_RCCEx_CRSConfig(&RCC_CRSInitStruct);
```

本原理图没有给 MCU 分配独立 VBUS 检测引脚，且 USB 5 V 通过 R19 与板上 5 V 相连。自供电时的 VBUS 检测、USB 连接控制和防止向 PC 回灌，需要硬件与 USB 电源策略共同处理，不能由这份 `.ioc` 自动解决。

## 6. RTC 与内部时钟

RTC 使用标称 40 kHz 的 LSI，异步预分频 124、同步预分频 319：

```text
40000 / (124 + 1) / (319 + 1) = 1 Hz
```

LSI 实际频率有较大偏差，上式只是标称日历时基，不保证走时精度。不要照搬旧 G0 的 32 kHz LSI 频率字段或 127/255 分频值。

PC14/PC15 已用于输出，不能同时开启 LSE。生成的 RTC 初始化仍需增加备份寄存器标志判断，避免每次复位重新写入初始日期。电池单独供电下的时钟能力需要另按芯片手册和电路验证；本配置不承诺无主电源时维持准确日历。

## 7. lwIP 内存缩减是必做项

F072 的 SRAM 为 `0x20000000`～`0x20003FFF`，共 16 KB。旧 map 文件显示 RW+ZI=28,880 B；旧配置仅 `MEM_SIZE=8192` 加 `8×1520` 的 pbuf payload 就占 20,352 B，已经超过芯片 RAM。

CubeMX 不提供本芯片的 SPI 外挂 CH390 lwIP 自动适配，因此 `.ioc` 不启用 CubeMX LWIP 中间件。继续手动移植仓库中的 lwIP 2.2.0 和 `ethernetif.c`。

下面是用于启动调试的缩减建议，**尚未在 F072 目标构建中验证，不是保证可用的最终资源配置**。必须依据同时在线的 TCP 客户端/服务器、UDP 发现和 DHCP 需要调整：

| 宏 | 建议起点 | 说明 |
| --- | --- | --- |
| NO_SYS | 1 | 保持裸机 Raw API |
| LWIP_IPV6 | 0 | 保持 IPv4 |
| MEM_SIZE | 3072 | lwIP 自有堆，不是 ProjectManager.HeapSize |
| PBUF_POOL_SIZE / PBUF_POOL_BUFSIZE | 2 / 1520 | 保持接收完整以太网帧能力，突发吞吐能力会下降 |
| MEMP_NUM_PBUF | 4 | 按发送队列使用量调整 |
| MEMP_NUM_TCP_PCB | 2 | 仅够两条活动 TCP 连接；重连/TIME_WAIT 可能需要更多 |
| MEMP_NUM_TCP_PCB_LISTEN | 1 | 一个监听端口 |
| MEMP_NUM_TCP_SEG | 8 | 与发送队列共同调整 |
| MEMP_NUM_UDP_PCB | 4 | 给 DHCP 与业务 UDP 留出资源 |
| TCP_MSS / TCP_SND_BUF / TCP_WND | 536 / 1072 / 1072 | 适用于小命令调试，需验证吞吐与连接行为 |
| TCP_SND_QUEUELEN | 8 | 与上述发送缓冲配套 |
| TCP_SNDLOWAT | 536 | 不保留大于新发送缓冲的阈值 |
| TCP_QUEUE_OOSEQ | 0 | 减少乱序缓存 |
| IP_REASSEMBLY / IP_FRAG | 0 / 0 | 首轮调试关闭；业务需要 IP 分片时重新评估 |
| IP_FORWARD | 0 | 本 MCU 不是路由器 |
| LWIP_HAVE_LOOPIF / LWIP_NETIF_LOOPBACK | 0 / 0 | 关闭不用的回环 |
| LWIP_DNS / LWIP_MDNS_RESPONDER / LWIP_SNMP | 0 / 0 / 0 | 无对应功能需求时关闭 |
| MIB2_STATS / LWIP_STATS | 0 / 0 | 同步关闭统计功能，验证驱动宏兼容性 |

关闭 MDNS 后同步把 `LWIP_NUM_NETIF_CLIENT_DATA` 调整为实际所需值。不要仅在文件末尾追加一批同名宏；应替换原定义，并检查 `lwip/init.c` 对 TCP 队列、窗口和发送阈值的一致性检查。

减小 pbuf 数量会增加丢包概率，必须验证 `ethernetif.c` 的内存不足丢包路径、DHCP 重试、TCP 重传和长时间运行。若必须维持旧版连接数和突发吞吐，优先选用更大 RAM 的 MCU。

最终 map 必须检查静态区、USB 类结构、lwIP 池、C 库堆和栈的总占用。USB Device 类的动态/静态分配方式也要核对；不能把 512 B C 库 Heap 与 3072 B lwIP Heap 混为一谈。保留栈余量并在实机测量栈水位。

## 8. 工程和源码迁移步骤

1. 使用 STM32CubeMX 打开本目录 `lwip_ch390d.ioc`。按提示安装 F0 V1.11.5 固件包；较新 CubeMX 如提示迁移，先另存再核对本说明中的关键配置。
2. Project Name 保持 `lwip_ch390d`，Project Location 选择本目录；先检查最终生成路径，不要指向旧 G0 工程。分文件生成 HAL 初始化和 MDK 工程。
3. 检查 `SystemClock_Config()`：HSI=ON、PLLSource=HSI、**PREDIV=RCC_PREDIV_DIV2**、PLLMUL=12、SYSCLK=PLLCLK、HSE/LSE 不启用，USBCLK=HSI48，RTC=LSI，并存在 CRS 配置。CubeMX 时钟树应显示 PLL 输入 4 MHz，PLLCLK/SYSCLK/HCLK/PCLK1 均为 48 MHz。F072 不能使用 64 MHz 或 96 MHz。
4. 检查 `MX_GPIO_Init()`：PB12 先输出高电平；78 路输出先写低再初始化；PD8 为输入；PF0/PF1/PC14/PC15 没有被振荡器占用；PA13/PA14 保留 SWD。
5. 检查 `MX_SPI2_Init()` 和 MSP：PB13/PB14/PB15 为 AF0，Mode 3，8 bit，软件 NSS，SCK=12 MHz。
6. 从旧工程迁移 `ch390d`、lwIP、`tcpudp` 与延时代码，修改 G0 HAL 头文件、SPI 句柄、GPIO 宏；不把旧 G0 的寄存器操作和 HAL 扩展结构整段复制。
7. 迁移控制协议到 USB CDC，按新接口重新核对输出映射。USB 中断只做数据搬运，网络处理留在主循环，持续调用 `sys_check_timeouts()`。
8. 重写 Flash 参数保存接口，详见下一节。按第 7 节缩减 RAM，并依据 map 复核。
9. EIDE 应重新导入生成的 F072 MDK 工程：CPU=Cortex-M0，宏=`STM32F072xB`，启动文件=`startup_stm32f072xb.s`，HAL/CMSIS 使用 STM32F0xx；不能沿用旧 G0 的 `.eide/eide.yml` 源文件列表和 scatter 配置。

`Keep User Code` 只保留 CubeMX 识别的用户代码区，不会自动完成跨系列移植。

## 9. Flash 参数保存

128 KB F072 的最后 2 KB Flash 页仍为 `0x0801F800`～`0x0801FFFF`，但旧 G0 的擦写 API 不能沿用：

- F0 的页擦除使用 `PageAddress` 和 `NbPages`，不能继续赋值 `erase.Page=63`。
- F0 使用 `FLASH_TYPEPROGRAM_HALFWORD` 的 16 bit 编程，不能继续使用 G0 的 64 bit `FLASH_TYPEPROGRAM_DOUBLEWORD`。
- 为参数保留最后一页后，链接器应用 Flash 区长度应为 `0x1F800`，而不是完整 `0x20000`；SRAM 长度为 `0x4000`。
- 原网络参数结构是 24 B，检查对齐、校验和、擦写错误处理和断电恢复；参数页和程序段不能重叠。

`.ioc` 的 MCU 选择和 Heap/Stack 设置不等同于已经预留参数页，需修改生成后的 MDK/EIDE 链接配置。

## 10. 硬件前提与上板核验

新版图中的电源路径应先复核：U15 和 U16 不应未经电源选择直接共同驱动 3.3 V；USB VBUS 与板上 5 V 的 R19 连接也没有防回灌能力。本配置不改变这些电路。

建议按顺序核验：

1. 先用 SWD 连接，检查 3.3 V、5 V、VDDIO2 和复位稳定性，确认 MCU 可下载。
2. 不插 USB 启动，确认系统运行、SysTick 正常，SPI2 SCK 实测约 12 MHz，CS 空闲高。
3. 读取 CH390 VID/PID 和 MAC，确认 INT 空闲低、事件高；验证插拔网线、DHCP、静态 IP、TCP 和 UDP。
4. 插入 USB，确认 CDC 枚举；测试配置帧分包/粘包、连续收发、拔插和 USB 未连接时网络继续运行。
5. 按 H1～H13 顺序逐一翻转 78 路，特别核对 H7 pin 5 的 PF3、H3 的 PB10/PB11，以及 PC13～PC15。
6. 验证 MCU 热复位、整板冷启动、参数保存/恢复、Flash 页边界、栈水位和网络持续负载。

## 11. 配置核验记录

## 12. 第一阶段移植状态

### 12.1 已接入的功能

- `Src/main.c` 的用户代码区调用 `network_app_init()` / `network_app_poll()`，保留 CubeMX 生成的 48 MHz 时钟、SPI2、RTC 和 USB 初始化。
- `Port/Src/CH390_Interface.c` 使用 SPI2、PB12 软件片选、PD8 高有效 INT；复用仓库原有 `ch390d/CH390.c` 的芯片寄存器和 PHY 操作。
- `Port/Src/ethernetif.c` 对接 lwIP 2.2.0，支持 pbuf 链收发、错误包丢弃、RX 指针恢复和有时间上限的 TX 等待；主循环每轮最多处理 4 个 RX 包，避免淹没 USB 和定时器处理。
- lwIP `sys_now()` 改用 `HAL_GetTick()`，不再依赖旧 G0 工程中固定 255 的 RTC SSR 分频假设。
- 默认 DHCP；启动时读到有效 Flash 静态配置则恢复静态 IP；保留 USB 的 0xA0～0xA4 网络配置命令。
- UDP 8888 保留 `DISCOVER` / `DISCOVERHOST` 请求响应。TCP 服务器保留 23000 端口；TCP 客户端保留连接 `192.168.1.100:2200`，在链路和 IP 可用后尝试连接并在断线后重试。
- USB CDC 接收字节进入环形队列，主循环解析原有 8 字节 `FE ... FF` 帧；支持 USB 拆包、连续多帧和错误头尾重同步。回复进入发送队列，发送缓冲在完成前保持有效，未插 USB 时不会等待枚举。
- `Port/Src/flash_net_cfg.c` 使用 F0 的页地址擦除、16 bit halfword 编程，保留原来的 24 字节记录布局和校验和。magic 最后写入，写入后做回读比较。

原 G0 工程和共享库中的 G0 适配文件没有修改；F072 使用独立的 `Port` 适配层和 `lwipopts.h`。MDK 工程已加入 Port、CH390 core 和共享 lwIP core 的源文件与包含路径。

### 12.2 按要求保留的旧控制函数

`Port/Src/legacy_control.c` 中的以下两个函数直接取自旧 `lwip_ch390d/Src/main.c`，包括 IO 写入、命令编号和函数内的网络配置处理均未修改：

```c
void tcp_recv_data_process(void);
void uart_recv_data_process(void);
```

可运行 `node tools/check_legacy_control.cjs` 验证逐字节一致性。当前 SHA256：

```text
tcp_recv_data_process:  d7adf69f11e3699a933f1be6503eb18d0233d9c1fb0a18158dfd9c251053975e
uart_recv_data_process: 0cb48af36e2c272558b4f272dc556f5abb8d68744ee3f86efe32de58f9fdf455
```

只修改了函数外部的 `send_net_mode_ack()` / `query_net_config()` 回复传输接口，使回复经 USB CDC 发送；`uart_recv_arr` / `uart_recv_data_process()` 名称保留，但数据入口是原生 USB，不启用硬件 USART。

旧通道编号与新板保留通信引脚的冲突如下，当前按用户要求保留，**不能将这几个通道视为已适配的普通输出**：

| 旧通道 | 原函数写入的 GPIO | 新板用途 |
| --- | --- | --- |
| 18 | PA12 | USB DP |
| 19 | PA11 | USB DM |
| 22 | PD8 | CH390 INT 输入 |
| 27 | PB15 | SPI2 MOSI |
| 28 | PB14 | SPI2 MISO |
| 29 | PB13 | SPI2 SCK |
| 30 | PB12 | CH390 片选；旧命令写入会直接影响片选状态 |

本次没有扩展到 78 路协议，也没有拦截、重映射这些旧命令。新板的最终通道映射须在协议确认后另行修改。旧处理函数没有检查 Flash 擦写返回值的行为也保持原样，因此收到模式确认回复不等同于已验证持久化成功。

TCP 服务器保留旧版“每次收到的 pbuf 总长必须为 8 字节且首字节为 FE 才接收”的条件，尚未增加 TCP 字节流拆包/粘包解析；上位机不能依赖一次 TCP write 对应一次接收回调。USB 的拆包/多帧处理由传输层实现，不改两个旧函数。

### 12.3 SRAM 与连接数量

当前实际配置位于 `Port/Inc/lwipopts.h`，不是共享目录的 G0 配置：

| 项目 | 实际值 |
| --- | --- |
| lwIP heap | 2560 B |
| RX pbuf pool | 3 × 1520 B payload，加各 pbuf 管理结构 |
| TCP MSS / WND / SND_BUF | 536 / 1072 / 1072 B |
| 活动 TCP PCB / 监听 PCB | 3 / 1 |
| TCP 业务连接 | 一个入站控制连接 + 一个出站客户端；额外 PCB 留给连接回收 |
| UDP PCB | 4，供 DHCP 与业务使用 |
| C heap / 保留栈 | 512 / 2048 B |

TCP 错误回调和发送失败采用返回/重试，不沿用旧代码在 `tcp_write()` 失败时原地无限循环的做法。RX 保留 3 个 pool buffer，是为了两个 TCP 方向发生背压时仍给 ACK/DHCP 留接收空间。突发流量和实际栈水位仍需上板测试。

本次 ARM GCC 10.3.1 `-Os` 链接结果：

```text
FLASH: 49116 / 129024 B (38.07%)
RAM:   15544 / 16384 B (94.87%)
```

RAM 统计包括 lwIP 静态池、USB、全局数据，以及链接脚本显式预留的 512 B C heap 和 2048 B 栈，另有 840 B 未分配。栈预留通过不等同于已经测得实机栈峰值。Flash 最后一页 `0x0801F800` 起的 2 KB 在 MDK/GCC 链接配置中均已排除，不放置程序。
