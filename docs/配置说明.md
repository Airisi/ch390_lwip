# STM32F072 网口控制器配置与使用说明

适用 MCU：STM32F072VBT6，LQFP100。  
适用硬件：网口控制器 2-V1.0。  
文档日期：2026-11-05。

本说明涵盖时钟、外设、接口分配、通信协议、网络参数存储和工程构建。硬件连接参见[网口控制器原理图](网口控制器2-V1.0.pdf)，芯片电气规格参见 [STM32F072 数据手册](DS_stm32f072vb.pdf)。

## 1. 系统配置

| 项目 | 配置 |
| --- | --- |
| 内核 | Cortex-M0，最高工作频率 48 MHz |
| Flash / SRAM | 128 KB / 16 KB |
| CPU 时钟 | 内部 HSI 8 MHz，经 PREDIV /2、PLL ×12，得到 48 MHz |
| HCLK / PCLK1 | 均为 48 MHz，AHB、APB 分频均为 /1 |
| USB 时钟 | 内部 HSI48，48 MHz；CRS 同步源为 USB SOF |
| RTC 时钟 | 内部 LSI，标称 40 kHz |
| 系统时基 | HAL 使用 SysTick，1 ms；lwIP `sys_now()` 使用 RTC SSR 累计换算 |
| 以太网接口 | CH390D，SPI2 主机接口 |
| 网络协议栈 | lwIP 2.2.0，IPv4、裸机 Raw API，`NO_SYS=1` |
| 配置接口 | 原生 USB FS Device，CDC 虚拟串口 |
| GPIO | 78 路输出，推挽、无上下拉、低速，初始化后为低电平 |
| 调试接口 | SWD，PA13 / PA14，外接 NRST |

HSI+PLL 为 CPU 和外设提供系统时钟，HSI48 独立用于 USB。网络初始化和主循环不等待 USB 枚举，未连接 USB 主机时仍可运行。

MCU 不启用 HSE、LSE；PF0、PF1、PC14、PC15 分配为 GPIO。CH390D 使用自身的 25 MHz 晶体，不向 MCU 提供系统时钟。

## 2. 时钟参数

### 2.1 CPU 与 SPI2

```text
HSI 8 MHz → PREDIV /2 → PLL 输入 4 MHz → PLL ×12 → SYSCLK 48 MHz
SYSCLK /1 → HCLK 48 MHz → APB /1 → PCLK1 48 MHz
PCLK1 /4 → SPI2 SCK 12 MHz
```

CubeMX 的关键参数如下：

```ini
RCC.PLLSourceVirtual=RCC_PLLSOURCE_HSI
RCC.PLLDivider=RCC_PREDIV_DIV2
RCC.PLLMUL=RCC_PLL_MUL12
RCC.SYSCLKSource=RCC_SYSCLKSOURCE_PLLCLK
RCC.AHBCLKDivider=RCC_SYSCLK_DIV1
RCC.APB1CLKDivider=RCC_HCLK_DIV1
SPI2.BaudRatePrescaler=SPI_BAUDRATEPRESCALER_4
```

CPU、HCLK 和 PCLK1 不得超过 48 MHz；SPI2 不得超过芯片规定的 18 Mbit/s。降低 SPI 速率时可选择 /8，得到 6 MHz。

### 2.2 USB 与 CRS

| 参数 | 设置 |
| --- | --- |
| USB Clock Source | HSI48 |
| CRS Source | USB SOF |
| CRS Prescaler | DIV1 |
| Polarity | Rising |
| Reload Value | 47999 |
| Error Limit | 34 |
| HSI48 Calibration | 32 |

CRS 使用内部同步路径，不占用 GPIO。USB SOF 校准依赖主机的有效 SOF 信号；内部 RC 时钟不作为精密计时基准。

### 2.3 RTC

异步预分频为 124，同步预分频为 319：

```text
40000 / (124 + 1) / (319 + 1) = 1 Hz
```

该结果为 LSI 标称频率下的日历时基。实际走时受 LSI 偏差和温度影响，不能据此承诺日历精度或电池独立供电时的持续计时能力。lwIP 毫秒时基由 RTC SSR 累计换算，同步预分频常量为 319。

## 3. CH390D 接口

| MCU 引脚 | LQFP100 管脚号 | 信号 | 配置 |
| --- | --- | --- | --- |
| PB12 | 51 | CH390_CS / SCS | 普通 GPIO 输出，初始高电平，低有效 |
| PB13 | 52 | SCK | SPI2_SCK，AF0 |
| PB14 | 53 | SDO | SPI2_MISO，AF0 |
| PB15 | 54 | SDI | SPI2_MOSI，AF0 |
| PD8 | 55 | CH390_INT | 输入、下拉，高有效轮询 |

SPI2 使用 Motorola 帧格式、双线全双工、8 bit、MSB first、Mode 3：CPOL=High，CPHA=2 Edge。NSS 为软件管理，NSS pulse 关闭。

CH390D INT 配置为高有效推挽输出。主循环检测 PD8，读取中断状态；收到数据或接收溢出时循环读取，直到 RX FIFO 没有待处理数据。链路变化事件先延时 65 ms，再更新 netif 链路状态。

初始化通过 `ch390_default_config()` 配置 PHY、MAC 接收和中断，读取内置 MAC 地址并注册网络接口。RSTB 未连接 MCU 控制引脚。SPI 使用阻塞式单字节传输，HAL 超时参数为 1000 ms；PHY、EEPROM 沿用寄存器忙等待。lwIP 发包前检查物理链路，并等待 TXREQ 清零后再写入 TX SRAM；链路断开返回错误，TXREQ 状态等待上限为 100 ms（SPI 调用自身 HAL 超时另计）。不提供驱动故障自动恢复。

## 4. GPIO 与输出接口

H1～H13 的 pin 1 为 12 V，pin 2 为 GND，pin 3～8 为经过 TXS0108E 转换的逻辑信号。连接器上的 12 V 为电源引脚，信号引脚的逻辑电平由转换器的 5 V 供电决定。

| 接口 | pin 3 | pin 4 | pin 5 | pin 6 | pin 7 | pin 8 |
| --- | --- | --- | --- | --- | --- | --- |
| H1 | PA10 | PA9 | PA8 | PC9 | PC8 | PC7 |
| H2 | PC6 | PD15 | PD14 | PD13 | PD12 | PD11 |
| H3 | PD10 | PD9 | PB11 | PB10 | PE15 | PE14 |
| H4 | PE13 | PE12 | PE11 | PE10 | PE9 | PE8 |
| H5 | PE7 | PB2 | PB1 | PB0 | PC5 | PC4 |
| H6 | PA7 | PA6 | PA5 | PA4 | PA3 | PA2 |
| H7 | PA1 | PA0 | PF3 | PF2 | PC3 | PC2 |
| H8 | PC1 | PC0 | PF1 | PF0 | PF10 | PF9 |
| H9 | PC15 | PC14 | PC13 | PE6 | PE5 | PE4 |
| H10 | PE3 | PE2 | PE1 | PE0 | PB9 | PB8 |
| H11 | PB7 | PB6 | PB5 | PB4 | PB3 | PD7 |
| H12 | PD6 | PD5 | PD4 | PD3 | PD2 | PD1 |
| H13 | PD0 | PC12 | PC11 | PC10 | PA15 | PF6 |

GPIO 标签按 MCU 引脚命名，例如 `OUT_PA00`、`OUT_PF03`。H7 pin 5 对应 MCU 的 PF3，即 U2 pin 22。

I/O 分配为：78 路输出、5 路 CH390D、2 路 USB、2 路 SWD，共 87 路 GPIO。增加硬件 UART 或外部振荡器时，需要重新分配引脚。

### 4.1 电气与启动状态

- PC13、PC14、PC15 的输出速度不超过 2 MHz、负载不超过 30 pF，并遵守芯片对输出电流和禁止用作电流源的规定。
- TXS0108E 用于逻辑电平转换，不能直接作为继电器、线圈等负载的功率驱动器。
- 输出低电平初始状态从 `MX_GPIO_Init()` 执行后生效。OE 固定接 3.3 V 时，上电和 MCU 复位期间的外部电平需要由硬件设计保证。

## 5. USB 配置接口

USB 使用 PA11=DM、PA12=DP，枚举为 CDC 虚拟串口。PA9、PA10 用作输出，不启用硬件 USART。

### 5.1 电阻装配

| 元件 | 装配状态 | 连接用途 |
| --- | --- | --- |
| R4 / R5 | 0 Ω | PA12→D+、PA11→D- |
| R9 / R12 | 0 Ω | PA10、PA9 接输出转换电路 |
| R3 / R7 | NC | PA12、PA11 的输出转换支路不接通 |
| R8 / R11 | NC | PA10、PA9 的 USB 转串口支路不接通 |
| U14 / X2 及配套 NC 元件 | 不装 | 使用 MCU 原生 USB |

R3 与 R9、R7 与 R12 分别属于互斥装配选项。装配方案须与 USB 和 GPIO 配置一致。

### 5.2 收发行为

USB CDC 的用户接收、发送缓冲各为 128 B。接收回调逐字节调用帧解析，采用 256 B 环形缓冲，按 FE 帧头、FF 帧尾提取固定 8 B 命令；错误头尾逐字节跳过，半帧保留等待后续数据。USB 数据包边界不作为命令边界。

解析结果写入单个 `uart_recv_arr[8]`，并置 `uart_recv_flag`，由主循环调用 `uart_recv_data_process()`。主循环处理前若又解析出新帧，会覆盖上一个结果；接口不提供多命令排队保证。上位机应逐条发送并等待应答，避免连续批量下发。

发送使用 256 B 队列，每次向 CDC 提交最多 64 B，提交缓冲在传输完成前保持有效。队列空间不足时写入返回失败，不提供端点接收背压或跨 USB 会话清理。断开重连后应重新查询当前配置。

配置端口默认不输出 printf 文本。调试时可将 `lwip_ch390d_f072/Port/Inc/retarget.h` 中的 `USB_PRINTF_ENABLE` 设为 `1`，或在编译器预处理宏中定义 `USB_PRINTF_ENABLE=1`；设为 `0` 则关闭重定向。修改后重新构建并下载固件。

启用后，printf 文本通过现有 USB CDC 发送队列输出，由主循环提交至端点，不等待主机读取；为协议回复保留 32 B 队列空间，调试空间不足时丢弃后续调试字符。USB 未枚举或主循环未处理发送时，日志暂存在有限队列中，不保证完整保留。调试文本与二进制配置应答共用同一接口，使用配置上位机时应关闭该宏。

启用时默认同时输出限频的 RX、TX、NET 诊断状态，字段含义及定位步骤见 [USB 调试排查说明](USB调试排查说明.md)。
CDC 波特率字段仅保存主机串口参数，不改变 USB 总线速率。USB VBUS 与板上 5 V 的连接、供电选择和防回灌措施应符合实际供电方案；引脚分配不包含独立的 MCU VBUS 检测输入。

## 6. 网络服务

| 服务 | 配置 |
| --- | --- |
| 启动地址模式 | 无有效静态配置时使用 DHCP；存在有效静态配置时自动加载 |
| TCP 控制服务器 | 本地端口 23000；各连接共享单个命令接收数组，建议一个控制端接入 |
| TCP 客户端 | 目标 `192.168.1.100:2200`，初始化时发起连接，断开或错误后定时重试 |
| UDP 设备发现 | 本地端口 8888 |
| 发现请求 / 回复 | ASCII `DISCOVER` / `DISCOVERHOST` |

UDP 发现请求长度为 8 B，回复长度为 12 B；回复发送至请求方 IP 和源端口。TCP 客户端的目标地址和端口在 `tcpudp/tcp_echo.c` 中配置。

### 6.1 TCP 接收边界

TCP 控制服务端仅接受单次接收回调中总长度恰好为 8 B、首字节为 FE 的数据，复制到 `tcp_recv_arr[8]` 并置接收标志，同时回显接收数据。主循环处理该标志后清空接收数组。命令处理函数进一步检查 FF 帧尾。

TCP 服务端收到对端 FIN 后调用 tcp_close() 完成关闭，由 lwIP 回收连接控制块。

TCP 应用层不拼接跨回调的半帧，不拆分一次回调中的多帧，也不维护命令队列。上位机应每次发送一条 8 B 命令并等待回显；TCP 仍可能发生拆包、合包，应用层不保证此类情况下命令被执行。回显不作为 IO 执行成功或参数持久化成功的确认。

服务端回显的 `tcp_write()` 使用循环重试，发送资源不足时可能阻塞网络处理。出站客户端按原始接收数据回显，断开或错误后通过 lwIP 定时器在 1 s 后重新发起连接。

## 7. 控制命令

TCP 和 USB 使用 8 字节帧，字节均按十六进制表示：

```text
FE CMD D0 D1 D2 D3 D4 FF
```

| 字节偏移 | 含义 |
| --- | --- |
| 0 | 帧头 FE |
| 1 | 命令码或通道号 |
| 2～6 | 数据字段 |
| 7 | 帧尾 FF |

命令由 `Port/Src/command_handler.c` 处理：`tcp_recv_data_process()` 处理 TCP 控制帧，`uart_recv_data_process()` 处理 USB 控制帧及网络配置帧。

### 7.1 IO 控制

```text
FE CHANNEL STATE 00 00 00 00 FF
```

`CHANNEL` 为 1～40，`STATE=01` 输出高电平，`STATE=00` 输出低电平。控制协议通道号与 H1～H13 连接器顺序分别定义，不能相互换算。当前固件不提供 41～78 路的控制命令。

| 通道 | GPIO | 通道 | GPIO | 通道 | GPIO | 通道 | GPIO |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | PC13 | 11 | PD3 | 21 | PD9 | 31 | PB11 |
| 2 | PC12 | 12 | PD2 | 22 | 保留 | 32 | PB10 |
| 3 | PC11 | 13 | PD1 | 23 | PC7 | 33 | PB2 |
| 4 | PC10 | 14 | PD0 | 24 | PC6 | 34 | PB1 |
| 5 | PB9 | 15 | PC9 | 25 | PA9 | 35 | PB0 |
| 6 | PB8 | 16 | PC8 | 26 | PA8 | 36 | PC5 |
| 7 | PB5 | 17 | PA15 | 27 | 保留 | 37 | PC4 |
| 8 | PB4 | 18 | 保留 | 28 | 保留 | 38 | PA7 |
| 9 | PB3 | 19 | 保留 | 29 | 保留 | 39 | PA3 |
| 10 | PD4 | 20 | PA10 | 30 | 保留 | 40 | PA5 |

以下编号涉及通信引脚，禁止作为普通 IO 通道使用：

| 保留通道 | 函数写入引脚 | 引脚用途 |
| --- | --- | --- |
| 18 | PA12 | USB DP |
| 19 | PA11 | USB DM |
| 22 | PD8 | CH390D INT 输入 |
| 27 | PB15 | SPI2 MOSI |
| 28 | PB14 | SPI2 MISO |
| 29 | PB13 | SPI2 SCK |
| 30 | PB12 | CH390D 片选 |

当前命令处理未屏蔽这些编号，发送相应命令仍会写入对应 GPIO 寄存器，尤其通道 30 会直接影响片选状态。上位机必须排除这些编号。

### 7.2 USB 网络配置

网络配置命令只通过 USB CDC 处理，IPv4 地址按四个八位字节顺序传输。

| 命令 | 帧格式 | 行为 |
| --- | --- | --- |
| 选择 DHCP | `FE A0 00 00 00 00 00 FF` | 启动 DHCP，清除已保存的静态参数，返回模式应答 |
| 选择静态模式 | `FE A0 01 00 00 00 00 FF` | 进入静态参数接收状态，返回模式应答 |
| 设置 IP | `FE A1 IP0 IP1 IP2 IP3 00 FF` | 接收 IP 地址 |
| 设置掩码 | `FE A2 M0 M1 M2 M3 00 FF` | 接收子网掩码 |
| 设置网关并应用 | `FE A3 GW0 GW1 GW2 GW3 00 FF` | 应用静态参数、写入 Flash，返回模式应答 |
| 查询配置 | `FE A4 00 00 00 00 00 FF` | 依次返回模式、IP、掩码、网关四帧 |

设置静态参数须按 A0→A1→A2→A3 顺序发送。示例：IP 为 `192.168.1.123`，掩码为 `255.255.255.0`，网关为 `192.168.1.1`。

```text
FE A0 01 00 00 00 00 FF
FE A1 C0 A8 01 7B 00 FF
FE A2 FF FF FF 00 00 FF
FE A3 C0 A8 01 01 00 FF
```

模式应答为 `FE A0 MODE 00 00 00 00 FF`，MODE 的 00 表示 DHCP，01 表示静态模式。查询中的 A1、A2、A3 帧分别携带当前 IP、掩码和网关。

模式应答不包含 Flash 擦写结果，也不保证 DHCP 已获得地址。需要确认断电保存效果时，应重新上电后查询实际配置。

## 8. Flash 与 SRAM

### 8.1 地址分配

| 区域 | 地址范围 | 用途 |
| --- | --- | --- |
| 应用 Flash，126 KB | `0x08000000～0x0801F7FF` | 程序、常量、变量初始值 |
| 参数 Flash，2 KB | `0x0801F800～0x0801FFFF` | 网络配置记录 |
| SRAM，16 KB | `0x20000000～0x20003FFF` | 全局数据、lwIP 内存池、USB 缓冲、堆和栈 |

网络配置记录为 24 B，包含 magic、网络模式、IP、掩码、网关、保留字节和校验和。存储使用页地址擦除及 16 bit halfword 编程，按记录地址顺序写入。记录无效时，启动地址模式为 DHCP。

参数存储为单页单记录，不提供多副本保持或日志恢复。

### 8.2 内存预算

| 项目 | 设置 |
| --- | --- |
| lwIP heap，`MEM_SIZE` | 2560 B |
| RX pbuf pool | 3 个；每个 payload 1520 B，另含管理结构 |
| TCP MSS / WND / SND_BUF | 536 / 1072 / 1072 B |
| TCP 活动 PCB / 监听 PCB | 3 / 1 |
| TCP segment pool | 12 |
| UDP PCB | 4 |
| 超时节点 | 12 |
| C 库 heap / 栈预留 | 512 / 2048 B |

`ProjectManager.HeapSize` 对应 C 库堆，`MEM_SIZE` 对应 lwIP 自有堆，两者分别分配。三块 RX buffer 由所有接收流量共享，不为 ACK 单独保留。为适配 16 KB SRAM，缩减 lwIP 堆、缓冲池和控制块数量，关闭 IPv6、DNS、mDNS、SNMP、RAW、IGMP、环回、IP 分片重组、TCP 乱序缓存和统计功能。保留 DHCP/AutoIP 协作、IPv4 分片发送及 IP 转发配置。

编译器、优化等级及功能开关会影响占用。发布构建须以实际 map 文件核对 Flash、SRAM 范围，并在目标板测量栈峰值和网络负载下的内存使用。

## 9. 工程结构与构建

| 路径 | 内容 |
| --- | --- |
| `lwip_ch390d_f072/lwip_ch390d.ioc` | CubeMX 配置 |
| `lwip_ch390d_f072/Src`、`Inc` | HAL 初始化、USB Device 接口 |
| `lwip_ch390d_f072/Port/Src`、`Port/Inc` | CH390D 硬件接口、lwIP 适配、命令处理、参数存储 |
| `lwip_ch390d_f072/MDK-ARM` | Keil 工程、启动文件、链接脚本 |
| `lwip_ch390d_f072/EIDE` | EIDE 工程 |
| `ch390d` | CH390 芯片核心及公共接口头文件；F072 硬件接口位于 `Port/Src/CH390_Interface.c` |
| `tcpudp` | TCP、UDP 实现及头文件，工程直接引用 |
| `systick` | 微秒延时实现及头文件，工程直接引用 |
| `lwip-2_2_0/src` | lwIP 核心源码和协议头文件 |

构建使用 ARM Compiler 5，CPU 选择 Cortex-M0，预处理宏为 `USE_HAL_DRIVER`、`STM32F072xB`。CubeMX 固件包为 STM32Cube FW_F0 V1.11.5，工程配置文件版本字段为 CubeMX 6.18.1 / DB.6.0.181。

打开 `lwip_ch390d_f072/EIDE/lwip_ch390d.code-workspace`，或使用 Keil 打开 `lwip_ch390d_f072/MDK-ARM/lwip_ch390d.uvprojx`。编译器安装路径按本机环境设置，构建前确认 `Port/Inc` 在包含路径中优先于共享配置目录，且包含共享的 `src/include/arch` 路径。

### 9.1 链接脚本

链接脚本位于：

```text
lwip_ch390d_f072/MDK-ARM/stm32f072vb_flash.scat
```

EIDE 的链接脚本路径相对于 `lwip_ch390d_f072/EIDE`：

```yaml
scatterFilePath: ../MDK-ARM/stm32f072vb_flash.scat
useCustomScatterFile: true
```

脚本限定程序 Flash 为 126 KB、SRAM 为 16 KB，并将启动向量表放在应用 Flash 首部。编译或下载配置不得把参数页并入程序区。

### 9.2 代码生成与调试

CubeMX 使用分外设 `.c/.h` 生成方式，并启用用户代码保留。生成后确认自定义源文件组、`Port/Inc` 包含顺序、主循环入口、USB 用户回调和自定义链接脚本配置完整。

SWD 使用 PA13、PA14 和 NRST。下载后可依次验证 USB 枚举、配置查询、DHCP 或静态地址、UDP 发现、TCP 连接和允许使用的输出通道。供电、PHY 链路、Flash 断电保存及外部负载行为以目标板实测结果为准。
